  Behaviour summary

  Pre-merge (ci.yml):
  - For PRs to main / maintenance/**: full pipeline + validate + rc S3 upload (only when manifest has -rcN).
  - For PRs to develop / feature branches: build + test + package + e2e (validate cascades-skipped, S3 upload cascades-skipped). Umbrella job's skippable list keeps these from failing the gate.
  - Required ruleset check: ci-required.

  Post-merge (release-tag.yml):
  - Fires only on merged PRs to main / maintenance/**.
  - Refuses to run if manifest still has -rcN or -dev.
  - Tag-last + idempotent: re-running after a transient failure is safe.
  - Back-merge PR opens automatically for main targets, not for maintenance hotfixes.

  Caveats worth knowing before this lands

  1. pull_request_target security model: the post-merge workflow runs with elevated permissions and access to secrets. It only checks out the merge commit (which is already on the protected branch), so the attack surface is limited — but be aware
   that any run: script in release-tag.yml reads from the merged code. The merged code is already PR-reviewed, so this matches the standard pull_request_target safety model.
  2. Back-merge PR triggering CI: PRs created by GITHUB_TOKEN don't trigger workflows by default. The back-merge PR will be opened but its own CI won't run automatically until someone manually closes/reopens it, or until you swap GITHUB_TOKEN for
   a PAT or GitHub App token. This is a well-known GitHub limitation, not a bug in the workflow.
  3. Plugin-validator uses npx @grafana/plugin-validator@latest — the validator is heavy first-run (downloads via npx). Pinning a version or pre-installing in the runner would speed it up. Acceptable as-is for now.
  4. set-version.sh is still called from build/test workflows that run for every PR. It now accepts -rcN, but it doesn't accept +sha8-stamped versions on release/hotfix branches. After it stamps a develop branch with +sha8, downstream callers
  (test workflow, package workflow) see the stamped version — which is fine because they're not on release/hotfix branches. The flow is unchanged for develop CI.
